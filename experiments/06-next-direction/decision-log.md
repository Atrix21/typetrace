Format as in experiment 3: **ID** · decision · reason. Experiments 1–5 are unchanged: no dataset, frozen config or stored result was edited.

- **E6-D01** · Scope (2026-11-16). Retrieval-only work on cached artefacts: no agent run, no billable call, no spend approval sought. Design on the frozen dev splits only; the held-out split is used once, under a protocol committed first. · The brief asked for a new direction with a real measurement and forbade bypassing spend approvals and frozen-evaluation safeguards.
- **E6-D02** · A development-only query set was added: mined bug-fix candidates that are not frozen tasks (Immich 67, Twenty 60 after dropping fixes whose functions no longer exist under the same key), on the pinned snapshots (`run.ts --silver`). · 23 dev tasks cannot separate effects below about ±0.05. · Known biases: the fix is present in the code; some reports state the fix. It is never used for a claim.
- **E6-D03** · Lean engine (`scripts/exp6/lean.ts`) accepted as the experiment harness after it reproduced the stored stage-1 `hybrid` ranking exactly on S 20/20, M 37/37, L 24/24 tasks. · The stage-1 evaluation process needs 6.1 GB on Twenty; the machine had 3–9 GB free during this work.
- **E6-D04** · Seven Immich dev bug-task graphs (deleted after stage 1) were rebuilt with the stage-1 build command into `.cache/exp6/graphs/M/`. Twenty needed no rebuild: every task graph is still in `.cache/exp3/agent/graphs/`.
- **E6-D05** · Change history rejected as a ranking signal (findings §3.1, §3.2). The prior is predictive alone and harmful in combination on five of five settings; commit-title text helps Immich and hurts Twenty on real issue text.
- **E6-D06** · File-level score fusion, seed-selection variants, propagation depth and graph weight, and graph-context embeddings rejected on design data (findings §3.3–§3.5). None was run on the held-out split.
- **E6-D07** · Reranking test pre-registered (`protocol.md`, commit 8c1fdfc) and run once. Result: Δ Recall@10 +0.005 [−0.035, +0.045], one-sided p = 0.40. Not supported. RRF k = 60 scored +0.027 on the same run; it was not the registered variant and is not adopted. · `Qwen/Qwen3-Reranker-0.6B` was downloaded from Hugging Face (public model, about 1.2 GB) for this test.
- **E6-D08** · Three performance-only changes to method code that experiment 1 hashed in `evaluation/configs/FROZEN-CONFIG.json` (`graph-engine.ts`, `hybrid-retrieval.ts`; also `compact-context.ts`, which is not in that list). Accepted because output is byte-identical to the stored stage-1 output: S 100/100 method–task outputs through `scripts/exp3/stage1.ts`, M 30/30 and L 28/28 through `scripts/exp6/bench-product.ts`. The recorded hashes are left as the experiment-1 record; four of those files had already changed during experiment 3 under the same rule (identical S results).
- **E6-D09** · Machine discipline.
  - Memory: at the start 2–5 GB was available. The owner allowed closing memory-heavy processes; only an idle Gradle daemon and an idle Kotlin compile daemon were stopped (both at 0% CPU, no build running), which freed about 3.4 GB. Other sessions and the browser were left alone.
  - Graph builds on M peak at about 1.9 GB, so the runner's gate for them is 6 GB available; L builds keep the 8 GB gate. One heavy job ran at a time.
  - Incident, fixed before any row was written: when the runner refused a graph build for low memory it exited with `immich_pr31074`'s fix still reverted in the shared Immich snapshot. The tree was restored with `git checkout -- .`; the runner now restores on that path too. Every task still starts with the clean-tree check, so no row was computed on a wrong tree.
  - Incident: a first history export used rename detection on the blobless clones, which made git fetch file contents from GitHub commit by commit for about five minutes. It was stopped; all history logs were produced with `--no-renames` and `GIT_NO_LAZY_FETCH=1`.
